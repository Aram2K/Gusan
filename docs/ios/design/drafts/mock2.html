Gusan on iPhone — plan and mockups, v2

Your keyboard, exactly as Apple's, with a Gusan strip on top. It appears whenever the keyboard opens, in every app.

1. Where Gusan lives

iOS lets nothing sit on top of another app's keyboard. The only way a Gusan strip can appear every time a keyboard opens is for Gusan to be the keyboard. So: a pixel-faithful copy of the iPhone keyboard (same keys, sizes, sounds, autocorrect behaviour where iOS allows it), and the row where Apple shows word suggestions becomes the Gusan strip. One honest difference: Apple's dictation key (the mic in the bottom row) exists only on Apple's own keyboard; iOS gives custom keyboards no microphone, so that corner is empty and the Gusan mic in the strip is the mic.

The strip, idle: mode chip (Smart or Agent) on the left; screen and mic icons on the right. Three things. The mic is the default: tap it and recording starts. The screen icon is selected by default: a screenshot is taken when you start and when you finish, so Gusan knows what's on screen. Tap it to deselect for a private moment; tap again to select. Everything Gusan does happens in that strip, or in one glass card that slides over the top key rows; the keyboard never disappears, and you never leave the app you're in.
Context rule: text you have selected is always sent as context, and the result replaces it. With the screen icon selected, Gusan gets the selection and the two screenshots. With nothing selected it uses the text around your cursor (and the screenshots, if the screen icon is selected). The strip shows what it's using while you speak. Listening indicator: while recording, the Dynamic Island glows (pulsing blue ring + waveform), so you can see Gusan is listening even with the keyboard half hidden. Connections add knowledge: with Google Calendar (or the iPhone Calendar) connected, "reply that I'm free" is answered from your real calendar, in Smart mode instantly and in Agent mode for booking.

4b. Logins the agent never sees

I checked how this is done today. H Company's Agents API has a built-in answer, and it is the right design for Gusan: Vaults. A vault holds one item per login (the sites it applies to, plus username, password, email, one-time-code secret). The agent never receives a secret. When the page it's on matches a stored site, the session offers the agent a single action, fill_secret_at, which types the value into the page outside the agent's context. No endpoint ever returns a secret, and for 2FA the session types the current code, never the secret itself. This is cloud-browser only, which is what Gusan uses.

StepWhat happensWho sees the password
1 · Add a loginIn Vault you tap Add from iPhone Passwords. iOS shows its own password picker; Face ID; iOS fills the login into Gusan's form. Gusan sends it over TLS to Gusan Cloud, which writes it straight into your personal H vault item (one vault per Gusan user, named by your user id) and stores only the site name and username for the list. The plaintext is never written to Gusan's database or logs.You, iOS, H's vault (encrypted). Not the agent, not Gusan's database.
2 · Agent hits a loginSessions start without the vault. When the agent reaches a sign-in page it stops and reports "needs a login for airfrance.com". Gusan Cloud marks the task awaiting_login and you get the card / notification.Nobody.
3 · You approveFace ID on your phone. Gusan Cloud then continues the session with the vault bound for that site only, for that session only. H's domain gating does the rest: the item is eligible only on that site or its subdomains.H types it into the page. The agent only sees "filled".
4 · AfterwardsThe binding ends with the session. Gusan Cloud records "login used: Air France, 09:41, session X" (no values). Remove a login in Vault and it's deleted from the H vault too.Audit entry only.
Rules that hold everywhere: secrets never appear in any prompt, log, screenshot caption, chat message or notification; the keyboard extension never handles a password (only the app does, after Face ID); Gusan Cloud talks to H with the server-side H key and never returns vault contents to a client; Privacy Mode disables the Agent entirely; no payment cards in v1 (the agent asks you to pay yourself in the confirm step).

Limits to know: iOS never lets Gusan read all your passwords at once, so each site is added once by you, with one tap + Face ID. Sites that sign in with Google/Apple or a code sent by SMS need you to finish that step yourself in the session chat (H can take over the one-time code only if you add the authenticator secret). Later option: connect a 1Password account instead of the H vault; H supports it natively and 1Password has an "Agentic Autofill" approval flow in iOS apps.

5. Decisions for you

  1. Keyboard look: an exact copy of Apple's keyboard (recommended), or Gusan's own style?
  2. Screen context on by default: this means Gusan Screen runs in the background while you use the phone, and iOS shows its red recording indicator the whole time. The strip icon only decides whether the frames are used. OK with the permanent indicator, or should Gusan Screen start only when you first select the icon?
  3. Vault: H vault per user, Face ID before every login, no payment cards in v1 (section 4b)?
  4. Back Tap: in phase 2, or later?
  5. Connections: start with Google Calendar + iPhone Calendar, read-only, in phase 2? Later: Contacts, Gmail, and letting the Agent create events (write access) after your Confirm.

Known limits that stay: a keyboard cannot take a screenshot by itself, so screen context needs Gusan Screen running (red indicator); the first mic tap per session opens Gusan for a moment (iOS rule); the glowing Dynamic Island is a Live Activity that Gusan starts during that first moment and keeps alive (quiet, just the logo) while it stays ready in the background, lighting up on each recording — iOS does not let an app start one from the background, so if iOS has closed Gusan, the hop happens again and restarts it; the agent's cloud browser starts with no logins; a free Apple ID means builds expire after 7 days and notifications arrive only when the app checks, not instantly.
